**Статус:** отложено (2026-05-19). Реализация кода **не начинаем**, пока владелец не приведёт в порядок **GTIN в Национальном каталоге** (отдельный GTIN на цвет/вариант; справочник 04). После готовности НК — вернуться к фазе 0 плана.

Полная детализация — в сессии планирования и в `.cursor/plans/` (файл `автоматизация_чз_игрушки_fa17f3dd.plan.md`). Ниже — выжимка для репозитория.

## Предусловие (блокер)

- Карточки товаров и **GTIN** в НК согласованы с артикулами ВБ (разный цвет → разный GTIN).
- Колонка **GTIN** в «Справочник товары» (книга 04).
- Правило: **«Отгрузка через»** = поставщик для папок на Яндекс Диске (`ship_via` в [main.gs](../../main.gs)).

## Пять этапов (канон)

| # | Этап | Автоматизация |
|---|------|----------------|
| 1 | Эмиссия (заказ КМ) | `order` |
| 2 | PDF этикеток поставщику | `fetch-supplier` → `upload-disk` |
| 3 | Отчёт о нанесении (после PDF от поставщика) | `apply-report` + `verify` |
| 4 | xlsx для таможни + декларация | `export-lk-xlsx`, `export-customs-pack` |
| 5 | Ввод в оборот после выпуска ДТ | `introduce` + `verify` |

## Инфраструктура (когда продолжим)

- Очередь: книга **04**, лист `Маркировка_задачи`; ключ `(Партия, Артикул ВБ, Спецификация, GTIN)`.
- ПК: Python `marking/`, УКЭП/CryptoPro (у вас уже настроено).
- Файлы: **Яндекс Диск** `Закупки/Реестры ЧЗ для таможни/{Отгрузка через}/{Спецификация}/`.
- Проверки после сбоев ЛК: `verify-reports`, лист `Маркировка_журнал`.
