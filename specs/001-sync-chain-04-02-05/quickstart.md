# Quickstart: Цепочка отгрузки 04→02→05

## Prerequisites

1. Script Properties в **книге 04** заполнены: `ORDERS_SPREADSHEET_ID`, `TRANSIT_SPREADSHEET_ID`, `COST_SPREADSHEET_ID`, `MASTER_REF_SPREADSHEET_ID`.
2. В **книге 05** задан `ORDERS_SPREADSHEET_ID` (для чтения «Сводной» в шаге 3 — как для одиночного safe).
3. В 01 собрана актуальная «Сводная» (меню или расписание).
4. Для тестовых строк: статус отгрузки + заполнен `Рейс` (`TR-YYYY-NNNN`).

## Deploy (after implementation)

Залить **целиком** в GAS-проект книги **04**:

- `main_04.gs`
- `sync_hub.gs`
- `gremlin_scheduled.gs`
- `sender_stock.gs` *(новый в составе 04)*
- `costing.gs` *(новый в составе 04)*

Книги **02** и **05** — обновить те же `sender_stock.gs` / `costing.gs` (рефакторинг impl).

## Manual test

1. Откройте книгу **04**.
2. `🔁 Синхронизация книг` → `Операционные потоки` → **Dry-run: цепочка отгрузки 04→02→05**.
3. Проверьте alert: три строки отчёта, без изменений в 02/05.
4. Откройте лист `SYNC_LOG` в 04: запись `Цепочка 04→02→05`, DryRun=YES.
5. Запустите **Цепочка отгрузки 04→02→05 (боевой)** → подтвердите.
6. В **02**: «Сводная» совпадает с 01; `Stock_Movements` обновлён.
7. В **05**: новые строки в «Партии_в_рейсе»; при добавлениях — лист `Партии_в_рейсе_бэкап_*`.
8. Повторите боевой запуск: существующие пары рейс+артикул **не** меняются (safe).

## Regression

- Отдельно: `Сводная 01→02 и 03` — по-прежнему копирует и в 03.
- Книга **02**: `Пересчитать движения и остатки` — работает локально.
- Книга **05**: `Партии_в_рейсе ← Сводная (01)` safe dry-run/live — работает локально.

## Failure drill

- Временно сломать `TRANSIT_SPREADSHEET_ID` → цепочка падает на шаге 1 или 2 с явным текстом; шаг 3 не выполняется.
