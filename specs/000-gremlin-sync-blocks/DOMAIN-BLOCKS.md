Каждый блок — логическая подсистема по меню/файлам. Статусы зрелости:

| Статус | Смысл |
|--------|--------|
| **Production** | Используется, документировано в README/PROJECT_CONTEXT |
| **Partial** | Есть код, неполная автоматизация или незавершённый UX |
| **Spec needed** | Нет spec в `specs/`; при доработке — Spec Kit |
| **Manual** | Намеренно только ручной запуск |

## Сквозные зависимости (критичные цепочки)

```text
Заказ (01, манер) → Сводная (01) → [04 цепочка] → Сводная (02) + транзит
                              ↘ [04 01→03] → Сводная (03) → планирование закупок
                              ↘ [05 safe] → Партии_в_рейсе → план/факт себестоимость
Рейс (05) ← события logistics ← ETA в 01 (пустые ячейки)
Оплаты (01/05) ← реестр (внешняя таблица)
МС ← syncOrdersWithMS (01), остатки (03)
```

## Приоритеты Spec Kit (backlog)

| P | Тема | Почему |
|---|------|--------|
| **P0** | Merge `001-sync-chain-04` | Закрыть фичу в main |
| **P1** | Отгрузка выделенных строк в рейс (01) | Узкое место до цепочки |
| **P2** | Hourly snapshots + шаги 2–3 цепочки (04) | Убрать ручной шаг после авто-снимка |
| **P3** | Playbook «закупки 03» (один документ + опционально spec) | Много меню, легко забыть 01→03 |
| **P4** | `refresh_qty` из цепочки (опционально) | Кейс Candy/TR-2026-0010 в checkpoint |
| **P5** | Единый health-check всех книг (04) | Сводная диагностика properties + листов |

## Что не трогать без spec

- **full_rebuild** «Партии_в_рейсе» в автоматике (конституция VI).
- Прямая связь **02 ↔ 05** (архитектурно запрещено; только через 01).
- Дублирование **МойСклад** как операционки (конституция I–II).
